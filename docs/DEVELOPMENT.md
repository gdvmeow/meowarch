# Виктория Терзян — архитектура и графика

Портфолио на React и Vite. Работает как статический сайт на [GitHub Pages](https://gdvmeow.github.io/meowarch/), отдельный сервер и база данных не нужны.

## Разработка

Нужен Node.js 20.19+ или 22.12+ (поддерживаемая LTS-версия).

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

Сборка сохраняется в `dist/`. Относительный `base` позволяет разместить её и в `/meowarch/`, и в корне собственного домена. Маршруты используют параметры URL, поэтому прямые ссылки не требуют серверного rewrite.

## Содержание

- `src/data.js`: проекты, размеры изображений, контакты, ссылки и фотография профиля.
- `src/scanStudies.js`: 15 работ из PDF-дампа и их переводы.
- `src/i18n.js`: русская, английская и китайская версии интерфейса и текстов.
- `src/pages/`: главная, каталог, проекты, профиль, контакты и восстановление неизвестных ссылок.
- `src/components/`: шапка и футер, языковое меню, карточка, иконки и модальная галерея.
- `src/routing.js` и `src/useNavigation.js`: прямые ссылки, фильтры, история, прокрутка и фокус.
- `src/PuttyText.jsx`: интерактивные буквы со стабильными областями наведения.
- `src/styles.css` и `DESIGN_SYSTEM.md`: токены, компоновка и правила визуального стиля.
- `public/assets/`: изображения и флаги. Шрифты загружаются локально из Fontsource.

В «О себе» биография, образование и инструменты пока оставлены рабочими плейсхолдерами в `copy.<language>.about`. Пользовательское фото отображается целиком, без деформации и генерации; исходный PNG хранится в `source-assets/about-photo.png`, публичный WebP не содержит EXIF. Имя использует тот же `PuttyText`, что в шапке и футере. Образовательное свидетельство находится на отдельной странице `?page=education`.

Неизвестный перевод нового проекта временно использует исходный текст; проверка содержания не даст забыть перевод перед публикацией. В `projects` находятся только предоставленные автором работы; сейчас это 20 работ: четыре первоначальных архитектурных проекта, «Сократ» и 15 работ из дампа (16 уникальных листов). Демонстрационные проекты и их изображения удалены. При добавлении изображений с другими пропорциями укажите их реальные `width` и `height` в данных.

«Сократ» — реальная работа из предоставленного двухстраничного PDF «ТЕРЗЯН В.С АД 1111 (2).pdf»: академический карандашный рисунок гипсовой головы, два ракурса. `scripts/prepare-socrates.py` воспроизводит подготовку изображений из исходного PDF с помощью Pillow и Poppler: нейтрализация цветового оттенка скана, плавная тоновая коррекция, локальное удаление двух проверенных пылинок и обрезка 12 px по краям листа (сверху первого скана — 24 px). Рисунок не перерисовывается, генерация не используется, исходный PDF не меняется. Портретные превью сохраняют пропорции листа целиком.

```sh
python3 scripts/prepare-socrates.py /path/to/source.pdf
```

Архитектурные листы подготавливаются скриптом `scripts/prepare-architecture.py` (Pillow, NumPy, Poppler). Он извлекает изображения в исходном разрешении, мягко корректирует тон без обесцвечивания, очищает видимые следы съёмки и сохраняет отдельные обложки. Исходные PDF остаются без изменений. Сопоставление четырёх входных файлов с проектами задано в `SHEETS`; названия проектов и описания определены по содержимому листов. В `cover` находятся данные единственной обложки; `images` содержит полные листы для страницы работы. Если `cover` не задана, используется первое изображение.

```sh
python3 scripts/prepare-architecture.py "/path/to/Telegram Desktop"
```

## PDF-дамп и документы

`content/scan-imports/terzyan-dump.json` содержит соответствие всех 24 страниц дампа выбранным листам, дубликатам и уже опубликованному «Сократу», причины выбора и SHA-256. В новый набор входят ровно 16 изображений; страницы 18 и 19 — разрез и план одного дома, поэтому новых карточек 15. Страницы 1–4 («Сократ») в новый набор не входят и не заменяют прежние assets.

```sh
python3 scripts/prepare-scan-dump.py "/path/to/ТЕРЗЯН В.С АД 1111.pdf" --metadata /tmp/prepared.json
```

Обработка только детерминированная: нейтрализация оттенка и неравномерного освещения бумаги, тоновая кривая, поворот, обрезка 12 px по краям. На странице 7 узкая проверенная маска очищает постороннее волокно на пустом поле, сохраняя подпись и рисунок. Для четырёх светлых чертежей применяется плавная локальная коррекция освещения. Генерации, дорисовки и удаления авторских линий нет. Все 24 извлечённых исходника и сравнение до/после сохранены локально в игнорируемой `backups/scan-review/index.html`; исходный PDF не изменён. В Git хранится manifest и воспроизводимый скрипт.

```sh
python3 scripts/prepare-education.py "/path/to/Муниципальное_бюджетное_учреждение (2).pdf"
```

Свидетельство о программе «Живопись» — отдельный документ, не проект и не часть 16 листов. Из трёх страниц публично сохранена только проверенная обложка без личных полей. Страницы с датой рождения, номером и подписями не копируются в `public` и не входят в историю Git. Исходный PDF сохранён отдельно; `content/scan-imports/education.json` фиксирует происхождение публичной производной. WebP не содержит исходного PDF-текста или EXIF.

Фото: Pillow `convert('RGB').save(..., 'WEBP', quality=94, method=6)` из сохранённого оригинала, без кадрирования, коррекции и генерации. В исходном PNG нет EXIF или дополнительных метаданных.

Обложки карточек отображаются в естественных пропорциях: без фиксированного соотношения контейнера, добавленного белого фона или обрезки при наведении. Асимметричная сетка, фильтры и режим списка сохранены. Только первая обложка видна в каталоге; остальные листы — внутри работы.

## Проверки интерфейса

```sh
npx playwright install chromium
npm run build
npm run test:browser
```

Если Chromium уже установлен, можно использовать его без скачивания:

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser
```

Браузерные проверки охватывают страницы, языки, узкие и широкие экраны, историю, фильтры, наведение на буквы, меню, галерею, буфер обмена, reduced motion и автоматическую проверку доступности. Node-проверки валидируют ссылки, данные, файлы и полноту локализации. При ошибке браузерного теста скриншот и trace сохраняются в игнорируемую папку `test-results/`.

## Публикация

В Settings → Pages источник публикации — GitHub Actions. Push в `main` запускает `.github/workflows/deploy-pages.yml`: проверку содержания и интерфейса, сборку и публикацию `dist/`. При неуспешной проверке текущая опубликованная версия сохраняется.
